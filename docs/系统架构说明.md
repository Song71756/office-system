# 新办公自动化系统 - 技术架构说明

## 一、系统概述

基于 **RBAC (Role-Based Access Control)** 模型设计的网上办公自动化系统，提供完整的组织管理、考勤打卡、公文流转、通知公告、日程管理等核心功能。

---

## 二、技术栈

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 核心框架 | Spring Boot 3.4.3 | Java 17 |
| 安全框架 | Spring Security | 身份认证基础 |
| 持久层 | MyBatis 3.0.3 | ORM 映射 |
| 分页组件 | PageHelper | MyBatis 物理分页 |
| 数据库 | MySQL 8.0.33 | 关系型数据库 |
| 身份令牌 | JWT (jjwt 0.11.5) | 无状态认证 |
| 工具库 | Lombok | 简化 POJO 代码 |
| 构建工具 | Maven | 依赖管理 |

## 三、系统功能模块

### 3.1 用户与权限管理 (User & Permission)

- **用户管理**：`/user/*`
  - 用户注册、登录、登出
  - 个人信息查看与修改
  - 密码修改
  - 用户分页列表 + 模糊搜索
  - 角色分配

- **角色管理**：`/role/*`
  - 角色 CRUD
  - 角色-权限绑定

- **权限管理**：`/permission/*`
  - 权限定义（菜单、按钮、API）
  - 树形权限结构
  - 权限-角色绑定

### 3.2 组织架构 (Department)

- **部门管理**：`/department/*`
  - 部门 CRUD
  - 部门树形结构查询
  - 用户归属部门管理

### 3.3 考勤管理 (Attendance)

- **打卡模块**：`/attendance/*`
  - 签到 / 签退（自动判断）
  - 考勤位置 & IP 记录
  - 个人考勤历史查询
  - 月度考勤统计

### 3.4 公文流转 (Document)

- **公文管理**：`/document/*`
  - 公文起草、编辑、提交
  - 多级审批流程
  - 审批意见记录
  - 视角隔离（创建者看所有状态，普通人只看已通过）
  - 状态：草稿(0) → 审核中(1) → 已通过(2) / 已驳回(3)

### 3.5 通知公告 (Notice)

- **公告管理**：`/notice/*`
  - 公告发布、编辑、删除
  - 阅读量统计
  - 分页 + 关键字搜索
  - 状态：草稿(0) / 已发布(1)

### 3.6 日程管理 (Schedule)

- **日程管理**：`/schedule/*`
  - 个人日程 CRUD
  - 状态：未开始(0) / 进行中(1) / 已完成(2)
  - 按用户隔离查询

### 3.7 文件管理 (File)

- **文件管理**：`/file/*`
  - 文件上传、下载、删除
  - 文件类型与大小校验

### 3.8 数据看板 (Stats)

- **统计模块**：`/stats/*`
  - 首页仪表盘数据聚合
  - 用户/部门/考勤/公文等多维度统计

## 五、核心设计亮点

### 5.1 细粒度权限控制 - `@CheckPermission`

**自定义注解**实现方法级权限拦截，支持 AND / OR 两种逻辑：

```java
// AND: 必须同时拥有所有权限
@CheckPermission({"user:add", "user:edit"})

// OR: 拥有任意一个权限即可
@CheckPermission(value = {"document:create", "document:edit"}, logical = Logical.OR)
```

**工作流程**：
1. `LoginInterceptor` 在请求到达 Controller 前拦截
2. 解析 `@CheckPermission` 注解获取所需权限
3. 从数据库实时查询用户权限列表
4. 根据 `Logical` 枚举执行权限匹配判定
5. 拒绝无权限请求，返回 403 Forbidden

### 5.2 JWT 无状态认证

- **Token 组成**：用户名 + 签发时间 + 过期时间（24小时）
- **签名算法**：HMAC-SHA256，密钥从配置文件读取
- **优势**：服务端无会话存储，支持集群部署与水平扩展

### 5.3 统一响应封装 - `Result<T>`

所有 API 返回统一格式：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { ... }
}
```

配合 `GlobalExceptionHandler` 实现全系统异常统一捕获与格式化输出。

### 5.4 视角隔离 - 数据安全设计

以 **公文系统** 为典型：

| 用户角色 | 可见的公文范围 |
|----------|----------------|
| 普通员工 | 仅已通过(status=2)的公文 |
| 公文创建者 | 本人创建的所有公文（包含草稿、审核中、已驳回） |
| 审批人员 | 所有已通过公文 + 待审批公文 |

### 5.5 物理分页 - PageHelper

使用 PageHelper 实现高效的数据库物理分页：

```java
PageHelper.startPage(pageNum, pageSize);
List<T> list = mapper.selectList();
return new PageInfo<>(list);
```

生成的 SQL 自动添加 `LIMIT` 和 `COUNT`，避免全表扫描。

### 5.6 业务解耦 - 三层架构

严格遵循 **Controller → Service → Mapper** 分层：

- **Controller**：参数校验、权限校验、响应封装
- **Service**：业务逻辑、事务管理
- **Mapper**：SQL 执行、数据映射

## 六、API 设计规范

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/xxx/page` | 分页查询列表 |
| GET | `/xxx/list` | 全量列表 |
| GET | `/xxx/{id}` | 详情查询 |
| POST | `/xxx/save` | 新增/修改 |
| POST | `/xxx/submit/{id}` | 提交申请 |
| POST | `/xxx/approve/{id}` | 审批操作 |
| PUT | `/xxx/edit` | 更新 |
| DELETE | `/xxx/delete/{id}` | 删除 |

**认证方式**：请求头携带 `Authorization: Bearer <token>`

## 八、技术总结

| 亮点 | 说明 |
|------|------|
| **RBAC 权限模型** | 基于角色的动态权限分配，支持细粒度控制 |
| **自定义权限注解** | `@CheckPermission` + `Logical` 灵活组合 |
| **JWT 无状态认证** | 支持集群部署，Token 24h 有效期 |
| **视角隔离设计** | 保障数据安全，实现多层级可见性控制 |
| **统一响应封装** | `Result<T>` 规范 API 输出格式 |
| **物理分页** | PageHelper 高效分页，避免内存溢出 |
| **三层架构** | Controller/Service/Mapper 职责清晰 |
| **全局异常处理** | `GlobalExceptionHandler` 统一错误返回 |
